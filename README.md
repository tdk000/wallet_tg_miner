# wallet_tg_miner — генератор «красивых» адресов Telegram Wallet (WalletTg) на C++

Портативная офлайн-утилита, которая подбирает адреса кошелька Telegram
(`WalletTg`, адрес вида `UQ...`) с заданным окончанием или префиксом.
Работает целиком на вашем компьютере, без обращения к сети и без чужой
фермы. Есть также готовое приложение для Android (см. раздел 11).

> ⚠️ Инструмент предназначен владельцу ключа. Сгенерированную фразу
> (мнемонику) нужно проверить на блокчейне **до** того, как класть на адрес
> средства. Подробности — в разделе «Предупреждения».

## 2. Сборка

Нужен любой компилятор C++17.

### Вариант A. Zig (самый портативный, не требует установки тулчейна)

```bash
zig cc -O3 -c monocypher.c -o monocypher.o
zig c++ -std=c++17 -O3 -c gpu_opencl.cpp -o gpu_opencl.o
zig c++ -std=c++17 -O3 -c wallet_tg_miner.cpp -o wallet_tg_miner.o
zig c++ -O3 wallet_tg_miner.o gpu_opencl.o monocypher.o -o wallet_tg_miner.exe -ladvapi32      # Windows
zig c++ -O3 wallet_tg_miner.o gpu_opencl.o monocypher.o -o wallet_tg_miner -pthread -ldl      # Linux
```

### Вариант B. GCC / Clang (Linux, macOS, MinGW)

```bash
g++ -std=c++17 -O3 -pthread wallet_tg_miner.cpp gpu_opencl.cpp monocypher.c -o wallet_tg_miner -ldl
```

На Linux флаг `-ldl` нужен для `dlopen` (на glibc ≥ 2.34 не обязателен),
на macOS он не нужен вовсе. На Windows с MinGW добавьте `-ladvapi32`.

### Вариант C. MSVC (Visual Studio)

```bat
cl /nologo /std:c++17 /O2 /EHsc wallet_tg_miner.cpp gpu_opencl.cpp monocypher.c /Fe:wallet_tg_miner.exe advapi32.lib
```

### Вариант D. Make / CMake

```bash
make            # или: cmake -B build && cmake --build build --config Release
```

Готовые однострочники — в `build.bat` (Windows) и `build.sh` (Linux/macOS).

## 3. Быстрый старт

**Самый простой способ (Windows):** дважды кликнуть `wallet_tg_miner.exe` — откроется
мастер с меню: **(1)** найти красивый адрес, **(2)** проверить фразу старой версии,
**(3)** показать демо-фразу старого дефекта (режим разработчика) — как в
Android-приложении. Либо запустить `start.bat` (меню). Окно не закрывается само.

> **Если адрес потом вводится в Telegram — выбирайте режим фразы.**
> В мастере это пункт **1** (он же по умолчанию). Тогда после импорта слов
> Telegram покажет **ровно тот же адрес**. Режим `subwallet` быстрее, но даёт
> адрес, который обычный клиент **не** воспроизводит.

> **Русский текст в консоли.** В Windows окно само переключается в кодировку UTF-8
> на время работы (иначе были бы «кракозябры»), а при выходе возвращает прежнюю.
> Если это не нужно (свой терминал с настроенной кодировкой) — выставьте
> переменную окружения `WTM_NO_UTF8_CONSOLE=1`.

Через командную строку:

```bash
# 1) Проверить, что криптография совпадает с эталоном (обязательно один раз)
wallet_tg_miner --selftest

# 2) Перебор мнемоники: адрес управляется словами (схема app, по умолчанию)
wallet_tg_miner --mode phrase --suffix TG

# 3) Перебор subwalletId: намного быстрее, но адрес зависит от subwalletId
wallet_tg_miner --mode subwallet --suffix TG
```

Пример вывода (режим `phrase`):

```

  public key  : 45ce63444e9db45251797dc26ebb1937f61f5034a66a6eeb0ac346432c60cc76
  mnemonic    : asset fence tourist setup surprise anchor across cluster young manual couple utility
  attempts    : 3081

             will show THIS address:
```

## 4. Опции командной строки

| Опция | Значение |
|-------|----------|
| `--suffix STR`  | адрес должен заканчиваться на `STR` (по умолчанию) |
| `--prefix STR`  | `STR` стоит сразу после тега `UQ`/`EQ` (позиция 2) |
| `--at N`        | сравнивать совпадение с base64-символа номер `N` (0..47) |
| `--ci`          | регистронезависимое совпадение |
| `--mode phrase` | перебирать мнемонику (по умолчанию). Адрес воспроизводится из слов при импорте в Telegram |
| `--mode subwallet` | перебирать только `subwalletId` (в ~3000 раз быстрее). Адрес воспроизводится только с тем же `subwalletId` |
| `--scheme app`  | схема `app` (по умолчанию): BIP39-PBKDF2 + SLIP-0010 `m/44'/607'/0'`; совпадает с импортом в Telegram |
| `--scheme ton`  | нативная схема TON (`@ton/crypto`); фраза импортируется в обычные TON-кошельки |
| `--words 12\|24` | длина мнемоники (по умолчанию 12) |
| `--threads N`   | число потоков (по умолчанию — все ядра) |
| `--mnemonic "..."` | зафиксировать мнемонику (для режима `subwallet`) |
| `--subwallet HEX`  | зафиксировать `subwalletId` (по умолчанию `0x7FFF7F11`) |
| `--testnet`     | тестовая сеть (`subwalletId = 0x7FFF7F7D`, тег `0xD1`) |
| `--max-tries N` | остановиться после `N` попыток |
| `--quiet`       | не печатать прогресс |
| `--bench`       | замерить скорость хеширования и выйти |
| `--selftest`    | прогнать встроенные тест-векторы и выйти |
| `--gpu`         | считать PBKDF2 + SLIP-0010 на GPU (режим `phrase`, схема `app`, 12 слов). Без OpenCL — автоматический откат на CPU |
| `--no-gpu`      | отключить GPU (GPU включается только явным `--gpu`) |
| `--gpu-info`    | показать найденное OpenCL-устройство и выйти |
| `--gpu-test`    | сверить GPU-деривацию с CPU и выйти |
| `--wizard`      | интерактивный мастер: поиск / проверка фразы старой версии / демо (запускается сам при двойном клике) |

Допустимые символы шаблона — алфавит base64url: `A-Z a-z 0-9 - _`.

Примеры:

```bash
wallet_tg_miner --mode subwallet --suffix wo1f --threads 8
wallet_tg_miner --mode phrase --suffix TG --words 24
wallet_tg_miner --mode phrase --scheme ton --suffix TG --words 24
wallet_tg_miner --mode subwallet --prefix AB --ci
wallet_tg_miner --mode subwallet --suffix TG --mnemonic "duty radar crop circle search fantasy crane live question gravity confirm corn"
```

## 5. Как это работает

### 5.1. Формула адреса

Адрес кошелька — это хеш `StateInit`, в котором:

* `code` — неизменяемый контракт-трамплин `WalletTrampoline`
  (24 байта, хеш `9149ae51…768`);
* `data` — хранилище: `0x00 | seqno:uint32 | subwalletId:uint32 | publicKey:256`.

```
hash     = SHA256( StateInit{ code, data } )
friendly = base64url( tag:u8 | workchain:i8 | hash:256 | crc16:u16 )
```

Для mainnet небьющиеся (non-bounceable) адреса начинаются с `UQ`.
Алгоритм хеширования ячеек (дескрипторы, паддинг, глубины и хеши ссылок)
полностью повторён байт-в-байт по эталону `@ton/core` — см. `--selftest`.

### 5.2. Два способа подбора и две схемы деривации

**Режим `phrase`** — меняется сама мнемоника. Поддерживаются две схемы
(`--scheme`):

* `app` (по умолчанию) — BIP39-деривация (функция `FU`):

  ```
  mnemonic -> PBKDF2-HMAC-SHA512(пароль=фраза, соль="mnemonic", 2048) -> seed
           -> SLIP-0010 ed25519, путь m/44'/607'/0'                   -> secret
           -> ed25519 public key                                      -> pubkey
  ```

  Мнемоника при этом — обычная **валидная BIP39** (12 слов с контрольной
  суммой).

* `ton` — нативная схема TON, ровно как `mnemonicToPrivateKey` в
  `@ton/crypto`:

  ```
  entropy = HMAC-SHA512(key = фраза, msg = "")
  seed    = PBKDF2-HMAC-SHA512(пароль = entropy, соль = "TON default seed", 100000)
  secret  = seed[0..31]        pubkey = ed25519(secret)
  ```

  Фраза при этом — «валидная TON-мнемоника»: любые слова из словаря,
  прошедшие тест `PBKDF2(entropy, "TON seed version", 390)[0] == 0`
  (вероятность 1/256). Такие фразы импортируются в обычные TON-кошельки
  без изменений.

`subwalletId` в режиме `phrase` фиксирован (`0x7FFF7F11`).

**Режим `subwallet`** — ключ фиксируется, перебирается `subwalletId`
(32-битное пространство). На попытку нужен только `SHA-256` + `CRC16` +
`base64`, поэтому это в тысячи раз быстрее. Но такой адрес воспроизводим
из мнемоники **только** тем клиентом, который использует тот же
`subwalletId`.

> **Важно.** Для самодельного майнера достаточно **12 слов**, у которых и
> адрес, и приватный ключ выводятся из `FU(фраза)` — это самосогласованно
> и сразу пригодно к тратам. Некоторые сервисы используют более хитрую
> схему: они отдают **24 слова = anchor(12) + signing(12)**, где адрес
> строится из `anchor` (слова 1–12), а рабочий ключ берётся из `signing`
> (слова 13–24) и подменяется в контракте транзакцией `ChangePublicKey`.
> Это нужно потому, что фразу майнит сервер и не должен знать ваш итоговый
> ключ. См. раздел 9.

### 5.3. Сложность

Ожидаемое число попыток ≈ `64^N`, где `N` — длина шаблона:

| Длина | Ожидаемо попыток | `phrase` app (≈0.5 тыс/с) | `phrase` ton (≈3/с) | `subwallet` (≈1.4 млн/с) |
|------:|-----------------:|--------------------------:|---------------------:|-------------------------:|
| 2 | 4.1·10³   | мгновенно | ~20 мин | мгновенно |
| 3 | 2.6·10⁵   | ~9 мин    | ~24 ч   | мгновенно |
| 4 | 1.7·10⁷   | ~9 ч      | ~2 мес  | ~12 с |
| 5 | 1.1·10⁹   | ~24 сут   | —       | ~13 мин |
| 6 | 6.9·10¹⁰  | —         | —       | ~14 ч |

(Скорости — на 4-ядерном AMD A8-6600K; на современном CPU в разы быстрее.
Схема `ton` в режиме `phrase` резко медленнее из-за PBKDF2 на 100 000
итераций и обязательной проверки «валидности» TON-мнемоники. С `--gpu`
строка `phrase`/`app` ускоряется ещё примерно в 30× — см. §7.1.)

## 6. Проверка корректности

`--selftest` сверяет реализацию с независимыми эталонами:

* `SHA256("abc")`, `SHA512("abc")`, `HMAC-SHA512`, `PBKDF2-HMAC-SHA512`;
* хеш контракта-трамплина `9149ae51…768`;
* контрольный вектор `pubkey → адрес` (свёрено с `@ton/core`
  `contractAddress`): `pubkey 000102…1e1f` →
  `UQAbzItZqG4Emy2gouoSMn5PXT--1pT6KuO_JlzeTOKAh_E7`;
* деривацию мнемоники `abandon … about` → `secret b477ef5e…` →
  `pubkey 7952e941…` → `UQD4d2pz…`;
* генерацию BIP39 для 12 и 24 слов (эталонные фразы из нулевой энтропии);
* нативную схему TON: `mnemonicNew`/`mnemonicToPrivateKey` из `@ton/crypto`
  → `pubkey 752e39c1…` → `UQDWukXC…` (и проверка `isBasicSeed`);
* старый детерминированный поток (см. §12): фраза #0
  `knife term question marble … exclude` → `UQB2dHHy…dUy9`, попадание
  `#6706`, промах и фраза с неверной контрольной суммой.

Всё это совпадает с эталонами `@ton/core` / `@ton/crypto` / `tweetnacl`.
Адреса, найденные утилитой, дополнительно сверялись с `@ton/core`
(`contractAddress`) — побайтово.

## 7. Производительность (`--bench`)

```
sha256          :      2022705/s
sha512          :      1536328/s
ed25519 pubkey  :         7061/s
phrase attempt  :          178/s   (на ядро)
subwallet try   :       449121/s   (на ядро)
gpu pbkdf2+slip :         5432/s   (gfx803)
```

`phrase`-режим упирается в PBKDF2 (2048 итераций) — это ожидаемо и
совпадает с оценкой ≈`64^N`. Для длинных шаблонов используйте
`--mode subwallet` или GPU.

### 7.1. GPU-ускорение (OpenCL)

`--gpu` переносит самую дорогую часть деривации — `PBKDF2-HMAC-SHA512`
(2048 итераций) и `SLIP-0010` (`m/44'/607'/0'`) — на видеокарту.
Публичный ключ ed25519 и хеш адреса TON остаются на CPU: это дешёвые
шаги, и их считают несколько потоков параллельно.

* **SDK не нужен.** OpenCL-рантайм (`OpenCL.dll` на Windows,
  `libOpenCL.so` на Linux, `OpenCL.framework` на macOS) подгружается
  динамически во время работы. Ни заголовков, ни `.lib` при сборке.
* **Автооткат.** Если OpenCL или драйвера нет, `--gpu` тихо возвращается
  на CPU — программа не падает из-за отсутствия GPU.
* **Корректность.** Ядро побайтово повторяет CPU-деривацию; `--gpu-test`
  сверяет GPU и CPU на наборе мнемоник и печатает `[ok]`. Стоит запустить
  один раз после смены драйвера.
* **Только `phrase` + `app` + 12 слов.** В остальных комбинациях
  (24 слова, схема `ton`, режим `subwallet`) работает обычный CPU-путь.

```bash
wallet_tg_miner --gpu-info              # показать найденную карту
wallet_tg_miner --gpu-test              # сверить GPU с CPU
wallet_tg_miner --gpu --suffix TG       # поиск с ускорением
```

На **AMD Radeon RX 550** (gfx803, AMD-APP 3584.0) выходит ≈**5400
дериваций/с** против ≈178/с на одном ядре CPU — примерно **30×**. Потолок
упирается в ed25519 на CPU и в 64-битную арифметику SHA-512 на бюджетном
gfx803 (там она эмулируется).

> Каждый старт с `--gpu` драйвер компилирует OpenCL-ядро: ≈10 с на gfx803.
> Для длительного перебора это разовые издержки. `--gpu-info` не требует
> сборки и отвечает мгновенно.

## 8. Безопасность

* **Офлайн.** Утилита не делает ни одного сетевого запроса.
* **CSPRNG.** Мнемоники и ключи генерируются из энтропии ОС
  (`RtlGenRandom` на Windows, `getrandom`/`/dev/urandom` на Unix),
  затем — поток ChaCha20. Никакого `rand()`/`srand()`.
* **Fail-closed.** При недоступности источника энтропии ОС программа завершается
  с ошибкой, а не использует запасной (детерминированный) генератор.
* **Приватный ключ не печатается.** Выводится только мнемоника —
  владелец может восстановить ключ сам.
* Исполняемый файл можно собрать статически и запускать на машине
  без интернета.

## 9. Предупреждения

1. **Про схему с 24 словами.** Сервис отдаёт **24 слова =
   anchor(12) + signing(12)**: адрес строится из `anchor` (слова 1–12), а
   рабочий ключ — из `signing` (слова 13–24), после чего ключ контракта
   подменяется транзакцией `ChangePublicKey`. Поэтому фраза из 24 слов
   *не* является обычной BIP39/TON-мнемоникой: адрес берётся из первой
   половины, ключ — из второй. Наш инструмент в режиме `phrase` (схема
   `app`) намеренно проще и самосогласован: **12 слов**, из которых
   выводятся и адрес, и ключ (`FU(фраза)`), без всякой ротации — такой
   адрес сразу пригоден к тратам.
2. **Выбирайте схему под свой кошелёк.** `--scheme app` (умолчание)
   повторяет app-деривацию и совпадает с импортом в Telegram
   Wallet; `--scheme ton` повторяет нативную TON-деривацию (`@ton/crypto`).
   Сгенерированную фразу сначала проверьте импортом (адрес должен совпасть
   с найденным) и только потом переводите средства.
3. **Режим `subwallet` не импортируется** обычным клиентом: он вернёт
   «адрес по умолчанию». Используйте его только для собственного
   клиента/деплоя с тем же `subwalletId`. Чтобы не ошибиться, смотрите
   блок `IMPORT CHECK` в выводе программы: он прямо пишет, появится ли
   этот адрес в кошельке (`YES`/`NO`) и почему.
4. Не передавайте мнемонику и приватный ключ третьим лицам и сервисам.
5. `seqno` для расчёта адреса всегда берётся `0` (состояние деплоя);
   адрес от него не зависит.
6. **Назначение и ответственность.** Инструмент предназначен
   исключительно для легитимных целей (брендинг, тестирование,
   образовательные задачи). Автор не несёт ответственности за
   неправомерное использование.

В каталоге `android/` лежит полноценное Android-приложение с простым
интерфейсом. Оно использует **тот же самый C++-код**
(`wallet_tg_miner.cpp`, `monocypher.c`, `gpu_opencl.cpp`) — криптография
не дублируется, ядро подключается через JNI.

* Полностью офлайн: в манифесте **нет ни одного разрешения**, даже
  `INTERNET`.
* Не нужны ни Termux, ни root — обычная установка APK.
* Собирается под `arm64-v8a` и `armeabi-v7a`; минимальная версия —
  Android 7.0 (API 24).

### Что умеет

* поиск по **окончанию** или по **началу** адреса;
* режим `phrase` (перебор мнемоники; адрес импортируется в Telegram —
  по умолчанию) и режим `subwallet` (очень быстрый, но не импортируется);
* выбор 12/24 слов;
* опция «не учитывать регистр» (аналог `--ci`);
* опция «использовать GPU (OpenCL), если доступно»;
* живой прогресс: попытки / скорость / время / вероятность;
* кнопки «Копировать адрес» и «Копировать фразу»;
* кнопка «Проверить себя (self-test)» — гоняет те же эталонные векторы,
  что и `--selftest`.

### Сборка APK

Нужны Android SDK, NDK (проверено на NDK 28.x) и JDK 17+.

```bash
cd android
./gradlew assembleDebug        # Windows: gradlew.bat assembleDebug
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

Если SDK лежит нестандартно, укажите путь в `android/local.properties`:

```properties
sdk.dir=/путь/до/Android/Sdk
```

Проект также открывается и собирается в Android Studio.

### Установка на телефон

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Либо просто скопировать APK на телефон и открыть (нужно разрешить
установку из неизвестных источников).

### Как пользоваться

1. Ввести окончание (или выбрать «в начале») — например `qq` или `_tg`.
2. Выбрать, что перебирать: мнемонику или `subwalletId`.
3. Нажать «Начать поиск» и дождаться результата; скопировать адрес и фразу.
4. Импортировать фразу в Telegram Wallet и убедиться, что адрес совпал.

> **Важно.** Как и в CLI, для импорта в Telegram используйте режим
> `phrase` (по умолчанию): адрес выводится из мнемоники. Режим
> `subwallet` годится только для собственного клиента с тем же
> `subwalletId`.

### GPU на Android

Флаг GPU пробует загрузить OpenCL-драйвер (`libOpenCL.so`) из вендорных
путей (`/vendor/lib64`, `/system/vendor/lib64` и т.п.). На большинстве
телефонов OpenCL не выставлен — тогда поиск автоматически идёт на CPU, и
приложение не падает.

### Автоматическая проверка (headless)

Приложение можно запускать без ручного ввода — удобно для скриптов и
проверки прямо на устройстве:

```bash
# self-test
adb shell am start -n com.wallettg.miner/.MainActivity --ez selftest true

# поиск по окончанию "qq" в режиме subwallet
adb shell am start -n com.wallettg.miner/.MainActivity --es pattern qq --es mode sub

# поиск по началу в режиме phrase
adb shell am start -n com.wallettg.miner/.MainActivity --es pattern TG --es place start
```

Поддерживаются extras: `pattern`, `place` (`end`/`start`), `mode`
(`phrase`/`sub`), `words` (12/24), `ci`, `gpu`, `selftest`. Результат
пишется в logcat с тегом `WalletTgMiner` (`WTM_SELFTEST`, `WTM_RESULT`).

## 12. Проверка фраз старой версии

В самых первых сборках был дефект: если системный источник энтропии оказывался
недоступен, генератор не завершался с ошибкой, а «подстраховывался» фиксированной
константой. Из-за этого все мнемоники становились предсказуемой функцией своего
номера в потоке — любой, кто знал дефект, мог восстановить ключ такой фразы.

Текущие сборки работают **fail-closed**: при недоступности энтропии ОС поиск
завершается ошибкой (`fatal: OS entropy source unavailable`), а детерминированные
данные не подставляются никогда. Старый поток оставлен в коде только для
проверки: он вызывается **исключительно** командами ниже и никак не связан с
`Rng::seed()`.

Проверить конкретную фразу (например, из старого бумажного бэкапа):

```bash
# фраза прямо в командной строке
wallet_tg_miner --check-fallback-phrase "word1 word2 ... word12"

# или из stdin — чтобы фраза не попала в историю оболочки
wallet_tg_miner --check-fallback-phrase - < phrase.txt
```

Коды выхода: `0` — совпадений нет, `2` — фраза найдена (она предсказуема, нужно
перевести средства на новый кошелёк), `1` — ошибка (неразборчивая фраза,
неизвестное слово, неверная контрольная сумма). По умолчанию проверяются первые
100000 фраз; лимит задаётся `--limit N`.

В интерактивном мастере на Windows то же самое доступно без командной строки:
пункт **2** меню — проверка фразы, пункт **3** — демо-фраза старого дефекта.

В Android-приложении то же самое доступно в разделе «Проверить фразу старой
версии»: фраза обрабатывается только на устройстве, не логируется, не копируется
и не сохраняется (поле помечено как нечувствительное к снимкам состояния).

Ограничения:

* проверка покрывает **только 12-словную схему `app`**
  (`m/44'/607'/0'`); 24-словная схема rotation (anchor + signing) **не**
  проверяется;
* отсутствие совпадения — **не** гарантия: поток длиннее заданного лимита;
* в режиме `subwallet` ключ берётся один раз, поэтому опасна только фраза #0
  (её первые 16 байт).

Демонстрационный режим `--insecure-demo-fallback [--index K]` печатает такую
фразу и её адрес; он спрятан за `--help-dev` и предназначен только для
разработчиков. Такие фразы **предсказуемы** — никогда не храните на них средства.
